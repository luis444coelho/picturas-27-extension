# Requisitos Funcionais: Comuns e Transversais (Pipeline Base de Vídeo)
### PictuRAS (v27.1) · Fase 1: Suporte a Vídeo Digital

Estes requisitos transversais garantem as políticas de integridade de sessão, controlo de quotas, gestão de tarefas assíncronas no broker AMQP (RabbitMQ) e persistência uniforme de recursos multimédia para todas as operações de vídeo (`UC-VID-000` a `UC-VID-015`).

---

|---|---|---|---|---|---|---|---|
| **REQ-VID-COM-001** | O sistema deve permitir iniciar uma operação de manipulação de vídeo apenas para um recurso de vídeo previamente carregado, íntegro e associado ao projeto do utilizador autenticado. | Deve ter | Refinado | ALT | UC-VID-000 a 005 (Pré-condições) | Porta de entrada de segurança e integridade de dados para todo o subsistema de vídeo. | Dado um utilizador autenticado, Quando submete um pedido de operação para um ID de vídeo inexistente ou pertencente a outro projeto, Então o pedido é rejeitado com código HTTP 404 ou 403 sem criar tarefa. |
| **REQ-VID-COM-002** | O sistema deve disponibilizar o resultado de qualquer operação de vídeo apenas após a conclusão bem-sucedida da respetiva tarefa de processamento assíncrono. | Deve ter | Refinado | ALT | UC-VID-001 a 005 (Pós-condição de Sucesso) | Evita a exposição de ficheiros corrompidos ou incompletos na galeria do utilizador. | Dado um processamento assíncrono em curso, Quando o utilizador consulta a galeria do projeto, Então nenhum artefacto temporário ou parcial é visível até à receção do estado `completed`. |
| **REQ-VID-COM-003** | O sistema deve associar automaticamente o vídeo resultante ao projeto como novo recurso independente após a conclusão bem-sucedida do processamento. | Deve ter | Refinado | ALT | UC-VID-001 a 004 (Passo final, Pós-condição, DQ-007) | Garante a persistência não destrutiva do resultado mantendo o histórico de transformações do projeto. | Dado o término com sucesso de uma operação de vídeo, Quando o processamento atinge `completed`, Então o novo recurso surge listado no projeto com metadados preenchidos e vínculo ao vídeo de origem. |
| **REQ-VID-COM-004** | O sistema deve validar todos os parâmetros de uma operação de vídeo na camada de API antes de registar a tarefa de processamento na fila assíncrona. | Deve ter | Mantido | NOVO | UC-VID-001 a 005 (Passos de validação) | Impede o consumo inútil de ciclos de computação nos workers com pedidos malformados ou incompletos. | Dado um conjunto de parâmetros introduzidos na interface, Quando o utilizador confirma a operação, Então a API valida tipos e limites antes de publicar mensagem no broker RabbitMQ. |
| **REQ-VID-COM-005** | O sistema deve rejeitar a criação da tarefa de processamento quando algum parâmetro for inválido, indicando o campo em falta ou incorreto. | Deve ter | Mantido | NOVO | UC-VID-001 a 005 (Exceções de parâmetros) | Facilita a usabilidade e a rápida correção por parte do utilizador sem qualquer débito de quota. | Dado um formulário com parâmetro fora dos limites suportados, Quando o utilizador submete a operação, Então a API responde com código HTTP 422 indicando o atributo causador da violação. |
| **REQ-VID-COM-006** | O sistema deve expor todas as operações de transformação de vídeo através de um contrato uniforme de tipo de operação e parâmetros, que permita executá-las isoladamente, como passo de uma cadeia ou em lote. | Deve ter | Novo | NOVO | UC-VID-008 a 012 (FA de utilização em cadeia/lote), UC-VID-014 (RN2), UC-VID-015 (RN3), DQ-017 | Permite compor operações sem implementações específicas por contexto de execução. | Dado o contrato `{operation, parameters}` de um filtro, Quando submetido isoladamente, como passo de cadeia ou num lote, Então é validado pelas mesmas regras e produz o mesmo efeito. |
| **REQ-VID-AUTH-001** | O sistema deve exigir um token JWT válido para autorizar a invocação de qualquer endpoint do subsistema de vídeo (upload ou manipulação). | Deve ter | Mantido | ALT | UC-VID-000 a 005 (Pré-condições, RN1, DQ-001) | Protege as rotas da API contra acessos indevidos e assegura a identificação inequívoca do utilizador responsável. | Dado um pedido HTTP sem cabeçalho Authorization ou com token expirado, Quando submetido a qualquer rota de vídeo, Então o sistema devolve imediatamente o código HTTP 401 Unauthorized. |
| **REQ-VID-AUTH-002** | O sistema deve rejeitar qualquer tentativa de execução de carregamento ou operações de vídeo por utilizadores não autenticados (perfil anónimo). | Deve ter | Mantido | ALT | UC-VID-000 a 005 (Pré-condições, RN1, DQ-001) | O suporte a vídeo exige persistência estruturada em projetos autenticados e controlo de capacidade. | Dado um visitante anónimo na plataforma, Quando tenta aceder às funcionalidades de vídeo, Então o sistema redireciona-o para a interface de autenticação/registo sem processar o pedido. |
| **REQ-VID-AUTH-003** | O sistema deve verificar a permissão de projeto exigida pelo tipo de operação de vídeo: leitura para consultar informações ou descarregar, e edição ou propriedade para carregar ou alterar recursos. | Deve ter | Refinado | ALT | UC-VID-000 a UC-VID-015 (pré-condições e RN de autorização) | Permite acesso de leitura aos casos de consulta e descarregamento sem autorizar alterações a recursos partilhados. | Dado um utilizador autenticado com permissão apenas de leitura, Quando consulta informações ou descarrega um vídeo concluído, Então o pedido é autorizado; quando tenta carregar ou transformar um vídeo, Então a API responde HTTP 403 Forbidden. |
| **REQ-VID-QUOTA-001** | O sistema deve verificar o saldo da quota diária de operações do utilizador registado antes de autorizar a submissão de uma tarefa de manipulação de vídeo. | Deve ter | Mantido | ALT | UC-VID-001 a 005 (Passo de confirmação, RN5, DQ-001) | Garante o cumprimento do modelo de negócio e impede a criação de tarefas sem crédito disponível. | Dado um utilizador registado com 0 créditos na quota diária, Quando tenta submeter uma operação de vídeo, Então a ação é bloqueada com notificação de quota esgotada. |
| **REQ-VID-QUOTA-002** | O sistema deve reservar exatamente 1 operação da quota diária do utilizador registado no momento da aceitação da tarefa de vídeo no estado `queued`. | Deve ter | Mantido | ALT | UC-VID-001 a 005 (Passo de aceitação, RN5, DQ-001) | Evita condições de corrida e submissões concorrentes que violem o teto diário de 5 operações. | Dado um utilizador registado com saldo de 5 créditos, Quando a tarefa de vídeo é aceite em fila, Então o seu saldo transitório é decrementado para 4 créditos. |
| **REQ-VID-QUOTA-003** | O sistema deve confirmar o débito definitivo da operação de quota reservada apenas quando a tarefa atinge o estado de conclusão com sucesso (`completed`). | Deve ter | Refinado | ALT | UC-VID-001 a 005 (Passo final, Pós-condição, DQ-001) | Respeita o princípio de cobrança exclusiva por trabalhos efetivamente concluídos e entregues ao utilizador. | Dado um processamento com crédito previamente reservado, Quando a tarefa atinge `completed`, Então o débito é consolidado sem decrementos adicionais. |
| **REQ-VID-QUOTA-004** | O sistema deve devolver o crédito de quota reservado ao saldo do utilizador registado em caso de cancelamento voluntário, rejeição ou falha de processamento. | Deve ter | Mantido | ALT | UC-VID-001 a 005 (Cancelamento, Exceções, RN6, DQ-001) | Impede a penalização injusta da quota do utilizador em situações anómalas ou desistências. | Dado um processamento que falha nos workers, Quando a tarefa transita para o estado `failed`, Então o saldo do utilizador registado é incrementado em 1 unidade de imediato. |
| **REQ-VID-QUOTA-005** | O sistema deve processar todas as operações de vídeo submetidas por utilizadores com perfil Premium sem aplicar nem contabilizar quota diária de operações. | Deve ter | Mantido | ALT | UC-VID-000 a 005 (FA Premium, RN5, DQ-001) | Concretiza o benefício contratual de acesso e utilização ilimitada conferido aos subscritores Premium. | Dado um utilizador autenticado com perfil Premium, Quando submete uma operação de vídeo, Então a tarefa é admitida sem verificação de quota e sem debitar contadores. |
| **REQ-VID-QUOTA-006** | O sistema deve debitar a quota da operação de vídeo à conta do utilizador que executa a operação, mesmo quando este opere sobre um projeto partilhado de outro proprietário. | Deve ter | Mantido | ALT | UC-VID-001 a 005 (Pré-condições, DQ-008) | Evita a exaustão maliciosa da quota do proprietário por convidados com acesso de edição. | Dado um projeto partilhado pelo utilizador A com o utilizador B, Quando o utilizador B submete uma operação de vídeo, Então a quota debitada é exclusivamente a do utilizador B. |
| **REQ-VID-QUOTA-007** | O sistema deve verificar, antes de aceitar um pedido com custo superior a 1 crédito (cadeia ou lote), que o saldo da quota diária do utilizador registado cobre o custo total, reservando a totalidade dos créditos no momento da aceitação. | Deve ter | Novo | ALT | UC-VID-014 (Passos 4-5, Exceção 4, RN8), UC-VID-015 (Passos 4-5, Exceção 4, RN4), DQ-014 | Evita aceitar trabalho que a quota não cobre e condições de corrida entre pedidos concorrentes. | Dado um utilizador registado com 3 créditos, Quando submete uma cadeia de 4 passos, Então o pedido é rejeitado com `QUOTA_EXCEEDED` e nenhum crédito é reservado; com 5 créditos, o saldo transitório passa a 1. |
| **REQ-VID-QUOTA-008** | O sistema deve calcular o custo de cada pedido de vídeo como 1 crédito por operação isolada ou junção, N créditos por cadeia de N passos e, num lote, o custo da operação ou cadeia multiplicado pelo número de vídeos concluídos, sem custo para o descarregamento e a consulta de informações. | Deve ter | Novo | ALT | UC-VID-006 (RN2), UC-VID-007 (RN2), UC-VID-013 (RN8), UC-VID-014 (RN7), UC-VID-015 (RN4), DQ-014 | Estabelece uma política única e previsível de consumo de quota para todas as operações de vídeo. | Dado uma cadeia de 3 passos aplicada em lote a 2 vídeos concluídos, Quando o lote termina, Então são debitados 6 créditos; dado um descarregamento ou uma consulta de informações, Então são debitados 0 créditos. |
| **REQ-VID-STORAGE-001** | O sistema deve armazenar os vídeos como recursos de projeto distintos de imagens, persistindo identificador único, nome de ficheiro, MIME type, duração, tamanho e data de carregamento. | Deve ter | Mantido | ALT | UC-VID-000 a 005 (Pré-condições, Pós-condições, DQ-003) | Modela com exatidão os atributos e características próprias de fluxos audiovisuais contínuos. | Dado um vídeo adicionado com sucesso ao projeto, Quando consultada a base de dados, Então o documento contém campos dedicados para duração em segundos, streams e resolução. |

| **REQ-VID-STORAGE-004** | O sistema deve registar nos metadados do vídeo resultante de uma cadeia ou junção a descrição ordenada dos passos aplicados, incluindo os parâmetros de cada passo e a posição de cada vídeo de origem na junção. | Deveria ter | Novo | NOVO | UC-VID-013 (Passo 7), UC-VID-014 (Passo 7), UC-VID-007 (FA1), DQ-003 | Complementa a lista `sourceVideoIds` com a receita completa da edição, permitindo auditar e reproduzir o resultado. | Dado o vídeo final de uma composição (V1 + filtro) + (V2 + remover áudio) → junção → marca de água, Quando inspecionados os metadados, Então constam as sub-cadeias com os seus parâmetros, a junção com a ordem (V1, V2) e a marca de água. |
| **REQ-VID-TASK-001** | O sistema deve executar as operações de vídeo através de tarefas assíncronas, devolvendo resposta HTTP inicial imediata com o identificador da tarefa e estado `queued`. | Deve ter | Mantido | ALT | UC-VID-001 a 005 (Passo de criação de tarefa, RN7, DQ-004) | Desacopla o gateway HTTP da latência de codificação e descodificação de vídeo. | Dado o envio de um pedido válido de recorte de vídeo, Quando a API responde, Então o tempo de resposta HTTP é inferior a 1 segundo e o corpo JSON contém `taskId` e `status: "queued"`. |
